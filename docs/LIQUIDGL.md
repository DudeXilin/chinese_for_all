# liquidGL в этом проекте — как с ним работать

Это инструкция для следующего ИИ/разработчика, который будет добавлять
или менять что-то, связанное с эффектом "жидкого стекла". Читай перед
тем, как трогать что-либо из списка ниже.

## Откуда это

Библиотека **не наша**, это открытый проект NaughtyDuk:

- Репозиторий: https://github.com/naughtyduk/liquidGL
- Демки: https://liquidgl.naughtyduk.com/demos/demo-1 (и demo-2..demo-5)
- Лицензия: MIT

Файлы лежат в `public/scripts/`:

- `liquidGL.js` — сама библиотека. **Никогда не редактировать вручную.**
  Если нужно обновиться до новой версии автора — просто скачать файл
  заново с GitHub (`scripts/liquidGL.js` в его репозитории) и
  заменить целиком.
- `liquidGL-helper.js` — официальная панель отладки автора (лежит
  там же в его репозитории).

Если через некоторое время автор снова что-то обновит — стоит свериться
с его README и changelog (there's a version comment in the header of
`liquidGL.js`), и при необходимости обновить оба файла тем же способом.

## Как это работает (коротко)

1. Один общий `<canvas>` на всю страницу — рисует WebGL-преломление
   фона под каждым "стеклянным" элементом.
2. `liquidGL({ target: ".some-class", ... })` находит все элементы с
   этим классом на странице и делает каждый из них "линзой": элемент
   становится (после короткой паузы на захват снимка фона) прозрачным
   изнутри, но остаётся в DOM как обычно.
3. `snapshot: "body"` — что именно фотографируется как фон для
   преломления (в нашем случае всегда весь `<body>`).

## Правило №1: контент — ВНУТРИ target, а не рядом

Наступил на эти грабли один раз — больше не наступать.

Правильно (как в demo-1 у автора):

```html
<a href="/lessons">
  <div class="cfa-glass">
    <span>Начать обучение</span>
  </div>
</a>
```

`div.cfa-glass` — это и есть target. Текст/иконка внутри него —
**обычный дочерний элемент**, не отдельный слой рядом. Это работает,
потому что `opacity: 0` и `background: transparent`, которые liquidGL
временно ставит на target во время захвата снимка, потом снимаются
(смотри `originalOpacity` в коде библиотеки) — контент внутри снова
становится видимым.

`pointer-events: none`, который liquidGL ставит на target насовсем —
не проблема: кликабельным должен быть **родитель** (`<a>` или
`<button>`), а не сам target. Клик проходит "сквозь" target к
родителю.

Неправильно (так делать не надо — именно так текст пропадал):

```html
<!-- НЕ ТАК -->
<a href="...">
  <div class="cfa-glass"></div>          <!-- отдельно -->
  <span>Текст</span>                      <!-- отдельно -->
</a>
```

## Правило №2: все target-элементы на одной странице должны иметь ОДИНАКОВЫЙ z-index

У эффекта один общий `<canvas>` на страницу, и его z-index
вычисляется как `(максимальный z-index среди всех target-ов) - 1`.

Если у одной кнопки z-index условно 100000, а у другой 9999 — canvas
окажется ВЫШЕ второй кнопки, и её содержимое визуально пропадёт под
canvas-ом. Именно так один раз сломался текст на кнопке "Начать
обучение".

**Правило: у всех fixed/absolute-обёрток с liquidGL-элементами на
одной странице должен быть один и тот же z-index.** В этом проекте
используется `z-index: 9999` для всех обёрток на `index.html`
(профиль-кнопка, кнопка "Начать обучение"), и отдельные небольшие
значения (например 120) на страницах, где liquidGL-элемент только
один (там неважно, что именно за число, лишь бы не 0/auto).

z-index достаточно поставить один раз на элемент, который: (а)
`position` не `static`, и (б) является ближайшим таким предком
target-а. Дочерним элементам ставить z-index не нужно — библиотека
сама поднимается по дереву предков и берёт первый найденный.

## Два разных места использования в проекте

1. **`public/index.html` (статичная главная страница).** Не React.
   Все скрипты подключены обычными `<script>` тегами в конце файла.
   Здесь используется класс **`.liquidGL`** (совпадает с дефолтным
   именем библиотеки) — сейчас это единственная кнопка "Начать
   обучение" (`public/js/main.js`). Профиль-кнопка на этой же
   странице использует класс `.cfa-glass` — отдельный вызов
   `liquidGL()` в `public/js/auth.js`, с настройками, подходящими для
   маленькой круглой кнопки.

2. **React-страницы (`/profile`, `/lessons`, `/lessons/[slug]` и
   т.д.).** Здесь есть компонент `components/glass-init.tsx`:

   ```tsx
   <script src="/scripts/liquidGL.js" />
   <GlassInit target=".cfa-glass" />
   ```

   `GlassInit` — это маленький клиентский компонент, который на
   монтировании вызывает `window.liquidGL(...)` с настройками из
   `DEFAULT_GLASS_OPTIONS` (экспортированы из этого же файла — это
   единый источник правды для дефолтных настроек эффекта). Если нужно
   переопределить что-то для конкретного места — передать `options`:

   ```tsx
   <GlassInit target=".cfa-glass" options={{ magnify: 1.5 }} />
   ```

   Новую "стеклянную" кнопку/карточку на React-странице делать так:
   1. Добавить `<script src="/scripts/liquidGL.js" />` на страницу
      (если его там ещё нет).
   2. Добавить `<GlassInit target=".cfa-glass" />` (один раз на
      страницу, даже если target-элементов несколько — один вызов
      подхватит их все).
   3. Разметку строить по Правилу №1 (контент внутри target) и
      Правилу №2 (одинаковый z-index у всех обёрток на этой
      странице).

## Дефолтные настройки (актуальные на сейчас)

Единый источник — `DEFAULT_GLASS_OPTIONS` в `components/glass-init.tsx`:

```js
{
  snapshot: "body",
  resolution: 1.5,
  refraction: 0.002,
  aberration: 0.1,
  bevelDepth: 0.04,
  bevelWidth: 0.264,
  frost: 0,
  shadow: true,
  specular: true,
  reveal: "fade",
  tilt: false,
  tiltFactor: 10,
  tiltEase: 400,
  magnify: 1.2,
  helper: false,
}
```

Кнопка "Начать обучение" на главной странице (`public/js/main.js`)
использует немного другие числа (по историческим причинам — так было
настроено ещё для старого большого окна в центре экрана, стиль решили
оставить). Если понадобится — можно привести к единому виду с
`DEFAULT_GLASS_OPTIONS`, но пока осознанно оставлено как есть.

## Панель отладки (helper)

`helper: true` в вызове `liquidGL()` включает официальную панель
автора (нужно, чтобы `liquidGL-helper.js` тоже был подключён
`<script>`-тегом). Сейчас включена на главной странице
(`public/js/main.js`), сдвинута в левый верхний угол через override в
`public/css/components.css` (у автора она жёстко прибита `!important`
в правый верхний угол, так что override сделан с более высокой
специфичностью, а не просто более поздним правилом).

## Правило №3: реальный контент body не должен быть `position: fixed`

Самая коварная ловушка, найдена в сентябре 2026 на `/lessons`.

`snapshot: "body"` работает, обходя дерево от `<body>` рекурсивно
(`buildNode`/`collect` в исходнике). Как только обход упирается в
элемент с `position: fixed` — **всё его поддерево целиком
пропускается**, обход в него не заходит вообще (не "элемент
невидим", а буквально "детей не существует" для снимка).

На `public/index.html` это никогда не всплывало, потому что реальный
контент страницы (`.main-content`) — обычный, НЕ `fixed` элемент.
`Fixed` там только сами декоративные кнопки (`.cfa-start-btn-link`,
`#cfa-profile-root`), а они и не должны ничего показывать позади
себя — они самоисключаются автоматически (см. ниже).

На `/lessons` когда-то было наоборот: единственным потомком `<body>`
был `<main class="lessons-page" style="position:fixed;inset:0">` —
то есть ВООБЩЕ ВСЁ на странице (весь контент, лента, всё) сидело
внутри одного `fixed`-контейнера. Снимку было физически неоткуда
взять пиксели — на любом `.cfa-glass` эффект выглядел как "запечённый
кадр"/шум, независимо от настроек liquidGL.

**Правило: если странице по дизайну нужно быть на весь экран без
скролла (как приложение), НЕ вешай `position: fixed` на корневой
контейнер контента.** Вместо этого блокируй скролл на `html`/`body`
(`overflow: hidden`, `height: 100%`), а корневой контейнер страницы
делай обычным `position: relative` с явной высотой (`100vh`/`100dvh`).
"Плавающие" элементы поверх контента (кнопка назад, декоративная
линза) по-прежнему могут быть `position: fixed` — это ожидаемо и не
ломает снимок, так как самоисключение фикс-элементов работает именно
для НИХ САМИХ, а не для остального контента страницы.

## Правило №4: под линзой должно двигаться через GSAP/JS, НЕ через CSS-transition

Уточнение к Правилу №3 (сентябрь 2026, `/lessons`). Даже когда снимок
технически работает (Правило №3 соблюдено), «живое» отслеживание
движущегося контента ПОД линзой не универсально — это подтверждено
официально, в таблице фич README библиотеки:

| Real-time Refraction (text animations) | ✅ |
| Real-time Refraction (CSS animations)  | ❌ |

«text animations» у автора — это анимации, которыми управляет GSAP
(`gsap.to/gsap.set`, задающий `transform` через JS на каждом тике).
«CSS animations» — это `transition`/`@keyframes` в чистом CSS. Именно
поэтому лента с типами уроков, которую двигал `transition: transform`
в CSS, никогда не «просвечивала» через линзу как живая — это в
точности неподдерживаемый случай, а не баг в нашей настройке.

Сам `public/index.html` работает по этому же правилу:
`public/js/main.js` двигает `.split`-строки через GSAP
(`gsap.from(split.lines, {...})` под ScrollTrigger), а не через CSS,
и именно эти GSAP-строки передаются в `liquidGL.registerDynamic(...)`.

**Правило: если хочешь, чтобы линза показывала что-то движущееся
живьём — двигай это через GSAP (`gsap.to`/`gsap.set`), не через CSS
`transition`/`animation`, и обязательно зарегистрируй элемент через
`liquidGL.registerDynamic()`.** Регистрировать удобнее всего в
колбэке `on.init` в самих опциях `liquidGL()` — он вызывается для
каждой linzy сразу после того, как она готова, и не зависит от
порядка эффектов между компонентами. Чтобы начальное состояние
анимации точно успело примениться ДО вызова `liquidGL()` (это
отдельно требует README), синхронизирующий эффект в React должен
быть `useLayoutEffect`, а не `useEffect` — layout-эффекты всей страницы
гарантированно отрабатывают раньше обычных `useEffect`, в том числе
из соседних/дочерних компонентов (там, где вызывается сам `liquidGL()`).

## Правило №5: у target-а не должно быть непрозрачного родителя в том же месте экрана

Самая незаметная ловушка, найдена в сентябре 2026 на `/lessons`.
Общий canvas либы **захардкожен в исходнике** на `position:fixed;
z-index:0` и добавляется напрямую в `<body>` (см.
`liquidGLRenderer` constructor, `this.canvas.style.cssText =
"...z-index:0;"`) — это НЕ настраивается через опции.

Когда target временно становится невидимым во время рендера линзы,
это открывает то, что находится СРАЗУ ЗА НИМ в его СОБСТВЕННОМ,
локальном контексте наложения (то есть — фон его прямого
DOM-родителя, если такой фон есть), а вовсе не автоматически
"дыру" до самого canvas где-то в body. Если у ближайшего
DOM-родителя target-а есть непрозрачный `background`, то именно
этот фон и покажется на месте линзы — визуально это выглядит как
"стекло есть, но оно просто прозрачный прямоугольник с тенью,
никак не реагирует на настройки Helper", хотя линза технически
создана (видна в `window.__liquidGLRenderer__.lenses`).

У кнопки "назад" это никогда не всплывало, потому что её родитель
(`<a class="lessons-back-btn">`) — без собственного `background`,
полностью прозрачный. У навигатора `.lessons-navigator-center`
раньше был ВЛОЖЕН внутрь тёмной "таблетки" `.lessons-navigator`
(`background: #303030`) — именно фон таблетки и перекрывал canvas.

**Правило: если элемент, которому нужен визуальный контекст
(тёмный фон, форма пилюли и т.п.), ДОЛЖЕН быть виден — не клади
`.cfa-glass`-target внутрь него. Сделай target СОСЕДНИМ (sibling)
элементом, позиционированным поверх той же точки экрана**, а не
дочерним элементом с непрозрачным родителем за спиной.

## Правило №6: не центрируй target через `transform: translate(...)`

Найдено в тот же заход, что и Правило №5, на `/lessons` — стекло
после исправления Правила №5 стало реагировать на Helper, но
рендерилось смещённым вправо-вниз примерно на половину своей
ширины/высоты.

Причина — в исходнике либы (`this.el.style.transform = ...`,
несколько мест — наклон/parallax при движении мыши, `tilt`) target
получает СВОЙ INLINE `style.transform`, которым либа управляет
полностью и перезаписывает каждый раз. Инлайн-стиль всегда
перекрывает `transform` из CSS-класса (это не вопрос специфичности —
инлайн `style` побеждает любое внешнее правило), поэтому если
центрировать target через классический трюк `left:50%; top:50%;
transform: translate(-50%,-50%)`, либа при первом же tilt-событии
(или просто при инициализации) заменит инлайн `transform` на свою
3D-строку для наклона — и наш `translate(-50%,-50%)` бесследно
исчезает, а элемент визуально "прыгает" на половину своего размера
вправо-вниз (ровно туда, где он был бы БЕЗ компенсирующего translate).

Ни один из рабочих референсов (`.cfa-start-btn`,
`.cfa-profile-button-glass`) не центрируется через `transform` —
у них либо `width/height:100%` внутри уже отцентрированного
родителя, либо фиксированная ширина.

**Правило: центрируй/позиционируй сам `.cfa-glass`-target ТОЛЬКО
через `left/top` + отрицательные `margin` (или через flex/grid на
родителе, если родитель — не сам target). Никогда не используй
`transform` на target-е для позиционирования** — этот CSS-property
полностью в распоряжении либы.

## Частые ошибки, которые уже случались

- **Текст/иконка пропадает** → почти всегда Правило №2 (разный
  z-index у обёрток на одной странице).
- **Дёргается на iOS при скролле** → в версии library ≥ на момент
  этой заметки (после обновления с v2.0.1 до v2.2.4) уже исправлено
  апстримом (пересчёт откладывается до конца скролла). Если проблема
  вернётся — сначала проверить, не устарела ли `liquidGL.js`.
- **Эффект видно, но кнопка не кликается** → клик должен ловить
  родитель target-а (`<a>`/`<button>`), не сам target.
- **Стекло "мерцает"/остаётся видимым, когда должно быть скрыто**
  (например, для выпадающего меню, которое то показывается, то
  прячется через `opacity`/`display`) → liquidGL не проверяет
  видимость предков перед отрисовкой линзы на canvas. Для элементов,
  которые именно **переключаются** (не постоянно на экране), проще и
  надёжнее использовать обычное CSS-стекло (`backdrop-filter: blur()`)
  вместо настоящего liquidGL — так сделано для выпадающего меню
  "Войти/Регистрация" на главной странице.
- **По краям стекла не искажаются буквы, много шума/артефактов,
  которые реагируют на `aberration`** (случай `/lessons`, сентябрь
  2026) → снова Правило №2, просто не сразу очевидное: на
  `/lessons` два target-а (кнопка "назад" и линза в навигаторе), и их
  ближайшие позиционированные предки (`.lessons-back-btn` и
  `.lessons-navigator`) имели РАЗНЫЙ z-index (120 и 110). Общий
  canvas встал на `120 - 1 = 119` — выше навигатора (110), поэтому
  его собственный рендер линзы был сломан/зашумлён. Симптом внешне
  выглядел как "битое преломление", а не как явная пропажа контента
  (как в примере выше с кнопкой) — стоит проверять Правило №2 при
  ЛЮБОМ визуальном баге эффекта на странице с несколькими target-ами,
  не только при пропадании контента.
